Knowledge-RAG · 我自己的 agentic 逻辑

Agentic 回路

不是"检索一次就塞给 LLM"，而是一个带判断的回路：搜 → 判断够不够 → 不够就多轮改写重搜 → 取细节 → 跨来源综合 → 出答案前硬核对，不过就回去重搜或拒答。

flowchart TD
    Q([问题]) --> PLAN[拆题 · 规划要搜哪些来源]
    PLAN --> SEARCH[search 混检
BM25 + 向量 + rerank]
    SEARCH --> JUDGE{命中够不够 / 对不对?}
    JUDGE -->|不够 / 不对| REFINE[改写查询
--course / --kind 缩范围]
    REFINE --> SEARCH
    JUDGE -->|够了| DETAIL{要整节上下文?}
    DETAIL -->|是| SECTION[section 取回整节]
    DETAIL -->|否| DRAFT[起草答案
只用检索到的原文]
    SECTION --> DRAFT
    DRAFT --> VERIFY[verify 护栏
真实引用 + 语义支撑 ≥ 地板]
    VERIFY --> GATE{通过?}
    GATE -->|BLOCK / 支撑不足| REFINE
    GATE -->|SUPPORTED| ANSWER([作答 · 引用块id + 页码])
    JUDGE -.->|库里确实没有| REFUSE([拒答: 知识库无依据])
    GATE -.->|反复不过| REFUSE

    class REFUSE refuse

检索 / 取节

search（BM25+向量+rerank）找证据，不够就改写重搜、缩范围；要细节用 section 取整节。都是本地确定性计算，≈免费。

判断 / 护栏

判断命中够不够；出答案前 verify 硬核对——引用必须真实、语义支撑≥地板。这是"禁止幻觉"的硬保证。

作答

只用检索到的原文，引用块 id + 页码，可回原书核对。

拒答

库里没有、或反复核对不过 → 明说"知识库里没有"，宁拒答不编造。

三个「自己的」设计

  • 纪律写死在 CLAUDE.md只引原文、必须核对、宁拒答不编造——是你的规则，不是通用 RAG。
  • veto 是确定性代码verify 用 embedding 算支撑分、一票否决，不靠模型自觉。
  • 能 workflow 就不 agent确定性检索交本地代码（便宜），只在推理/改写/综合/判断处动用 LLM 自主性。
  • 多轮兜底单发检索会漏的题（如跨语言 HITL），多轮改写 + 跨来源综合能答对——这就是 agentic 比简单引索强的地方。
